# Проект Android-версии NeXXXUs

Исходная точка — приложение `android/` версии **0.1.2**. Оно уже говорит с Linux по HELLO v3: чат и файл кусками по 16 КБ, те же двенадцать слов, тот же отпечаток. Сейфа 0.10.0 на телефоне нет.

Цель проекта — не «ещё один мессенджер», а тот же узел, что Linux, с явным включением ноды. Пока нода выключена, телефон остаётся клиентом и чужой диск не обещает.

iOS в этот проект не входит. На Apple позже возможен только клиент, без приёма чужих чанков.

## Чего не делать в первой поставке

- Не встраивать фиктивный `.onion` и не писать «Tor включён», если нет настоящего SOCKS.
- Не переносить веб-биржу и баланс NXX.
- Не принимать оплату.
- Не обещать три копии, если контактов меньше.
- Не класть открытую папку `drive` во внешнее хранилище без отдельного предупреждения. На телефоне открытая копия сейфа опаснее, чем на своём сервере.
- Не подписывать выпуск отладочным ключом, когда сборка уходит дальше своей лаборатории.

## Как устроен 0.1.2

Язык — Java, SDK 34, минимальная система — Android 7. Сеть — свой TCP в `NodeSession`, криптография — `Identity`, `Aead`, `Hkdf`. Служба `MeshService` держит процесс, пока система позволяет. Интерфейс — один экран: слова, прослушивание, контакт, чат, файл.

Этого достаточно, чтобы два телефона в одном Wi-Fi обменялись текстом. Этого мало, чтобы телефон стал частью сейфа Linux.

## Принцип переноса

Не писать второй протокол. Каждый шаг считается готовым, только если телефон и текущая Linux-нода проходят один и тот же сценарий. Векторы ключей уже общие. Дальше общими должны стать журнал, чанк и строка контакта.

Панель Linux остаётся эталоном. Телефон подстраивается под неё, а не наоборот.

## Очередь работ

### Этап A — выпуск, которому можно доверять

Срок по смыслу: первый, ничего нового в протоколе.

- Отдельный ключ подписи release. Отладочный ключ оставить только для `debug`.
- Версия в `versionName` больше не притворяется полной нодой. Пока нет журнала, в интерфейсе прямо написано: «чат и файл, без сейфа сети».
- Экран слов нельзя пролистать без подтверждения, что они записаны. Это уже почти так; проверить на чистой установке.
- Инструкция в самой программе: второй стороне нужен доступный IP, `127.0.0.1` не годится.
- Автотест, который уже есть, гоняется перед каждой сборкой APK. Плюс один ручной прогон: телефон и Linux 0.10.0 в профиле `lab`, чат и файл в обе стороны. Сейф при этом не обязан совпасть.

Готово, когда посторонний человек ставит APK и не думает, что включил облако.

### Этап B — тот же сейф, что Linux

Это первая настоящая версия телефона как клиента сейфа. Нода хранения ещё выключена.

- Перенести журнал `map.bin`: операции, подписи устройства и ноды, отзыв, сливание по подписям, а не замена журнала целиком.
- Перенести нарезку 16 КБ, nonce копии, идентификатор как хеш шифртекста, открытие только ключом владельца.
- Принять и отдать слепую копию, ответ на проверку случайного чанка, льготу 24 часа и местный штраф.
- Контакт лабораторного профиля тот же `nexxus:1:…`.
- Телефон не слушает чужие чанки, пока пользователь не включил ноду. На этом этапе выключателя ноды ещё нет, приёма чужого нет.
- Два телефона и одна Linux-нода: файл, положенный на телефоне, читается на Linux после обмена журналом. И наоборот.

Готово, когда `map.bin` с телефона открывается Linux-нодой с той же фразой, а испорченная подпись отвергается.

На этом этапе лук не обещать. Прямой TCP честно назван лабораторным.

### Этап C — телефон как нода по желанию

Включается отдельным действием, не при первом запуске.

- Пользователь видит свободное место и потолок. Пока не сделана проверка 16 ГиБ, телефон в нелабораторном режиме чужое не принимает. Для своих испытаний остаётся явный лабораторный потолок, как 64 МиБ на Linux, и эта цифра написана на экране.
- Чужой чанк хранится отдельно от своих файлов. Выключение ноды перестаёт принимать новое и не притворяется удалением уже принятого, пока журнал владельца сам не попросил снять копию.
- Экран предупреждает: приложение должно жить, экран может быть погашен, система всё равно может убить процесс. Это ограничение Android, его не прячут за «вечную ноду».
- Служба показывает постоянное уведомление, пока нода включена. Без уведомления режим не стартует.
- Проверка из Linux: телефон отвечает на случайный чанк; после принудительной остановки ответа нет, и Linux не считает копию живой.

Готово, когда старый телефон на зарядке в своей сети держит чужой шифртекст и не показывает его пользователю этого телефона.

### Этап D — лук

Только после этапа B. Анонимность не ставится раньше совместимости сейфа.

- Предпочтительный путь — SOCKS уже запущенного Tor, в первую очередь Orbot или другой местный SocksPort. Приложение не выдумывает имя лука.
- Если позже встраивается бинарник Tor, имя берётся только из его `hostname`, как на Linux. Нет бинарника и нет SOCKS — профиль не включается.
- Слушать с телефона наружу в луковом профиле нельзя: только localhost плюс скрытая служба.
- Лабораторный контакт с IP в луковом профиле отвергается.
- Проверка: телефон и Linux `test-tor-live` либо два телефона через два разных лука обмениваются одним сообщением и одним файлом сейфа.

Готово, когда в описании экрана нет слова «анонимно» без живого `.onion`.

### Этап E — очередь, описание файла, майнер

Их переносят с Linux 0.10.0 как есть, без совместимости с simplexmq.

- Очередь: телефон открывает её на знакомом узле, шлёт шифртекст, чужой отпечаток забрать сообщение не может.
- Описание файла без адреса и порта собирается на второй стороне, хеш сверяется.
- Флаг майнера на телефоне не показывается, пока нет проверки оплаты. До этого телефон может только хранить в лабораторном потолке, без слова «аренда».

Оплата — отдельный будущий этап и в этот проект не входит. Без разбора настоящей транзакции кнопки «купить место» не будет.

## Экран

Не копить вкладки веб-консоли. На телефоне четыре понятных места:

1. **Слова и устройства** — фраза один раз, список своих устройств, отзыв другого устройства.
2. **Связь** — профиль `lab` или `onion`, строка контакта, состояние канала.
3. **Сейф** — файлы, «у себя» и число чужих копий. Не процент «облака».
4. **Нода** — выключатель, свободное место, лабораторный потолок, уведомление. Пока выключено, экран короткий.

Чат остаётся, но не становится главным обещанием.

## Испытания

| Прогон | Участники | Ожидание |
|---|---|---|
| A | два телефона, один Wi-Fi | чат и файл, как сейчас |
| B | телефон и Linux | один `map.bin`, файл открывается с обеих сторон |
| B | испорченный журнал | телефон не принимает чужую подпись |
| C | телефон-нода и Linux-владелец | ответ на проверку чанка; после убийства процесса копия не вечная |
| D | телефон и Linux через Tor | одно сообщение по `.onion`, прямого IP в контакте нет |

Пока прогона B нет, версию телефона не поднимают до 0.10 и не пишут в магазине приложений «децентрализованное хранилище».

## Сборка

Каталог `android/`, JDK 17, Android SDK 34.

```bash
cd android
gradle assembleDebug
```

Release собирают только своим ключом подписи, когда он заведён. Готовый APK кладётся в релизы [NeXXXUs-Grok](https://github.com/PerfectFriend/NeXXXUs-Grok) с пометкой этапа: «0.1.x чат» или, позже, «сейф, без лука». В одном релизе не смешивают эти подписи.

## Порядок относительно Linux

Linux 0.11 по заданию сначала закрывает квоту `S / 3` и порог 16 ГиБ. Android этап B можно вести параллельно: журналу квота не мешает. Этап C на телефоне не включает приём чужого «сколько влезет», пока Linux сам не научится отказывать при нехватке 16 ГиБ. Иначе телефон станет дырой, которую серверная нода уже признала ошибкой.
