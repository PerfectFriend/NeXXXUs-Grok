# Аудит NeXXXUs

Дата: 1 ноября 2026. Срез кода: Linux **0.10.0**, коммит `210a2aa` в [NeXXXUs-Grok](https://github.com/PerfectFriend/NeXXXUs-Grok). Android остаётся **0.1.2**. Веб-консоль в этом дереве — не нода.

Аудит отделяет то, что исполняется и покрыто тестом, от того, что написано как цель. Цель продукта не отменяется. Несделанное нельзя показывать пользователю как уже работающее.

## Три разных программы

| Слой | Где лежит | Что это на самом деле |
|---|---|---|
| Linux-нода | `linux-node/` | Единственная нода, в которой есть сейф, копии, проверка чанка, лук, очередь, описание файла и флаг майнера |
| Android | `android/` | Телефонный клиент чата и файла по прямому TCP. Сейфа сети, Tor, очереди и майнера нет |
| Веб | `src/lib/nexxus/` | Учебный интерфейс в браузере. Состояние лежит в `localStorage`. Порт не слушает, чужие чанки не хранит, деньги не двигает |

Их нельзя складывать в одну версию. Фраза BIP39 на всех трёх считается одинаково, но журнал `map.bin` понимает только Linux.

## Что Linux 0.10.0 делает по-настоящему

Проверено локальными тестами `npm test` и одним живым прогоном Tor.

- Корень — 12 слов BIP39. На диске фраза лежит в `identity.bin`, закрытом `machine.key`. Потеря обоих файлов без записанных слов не лечится.
- Канал: X25519, четыре секрета Диффи—Хеллмана, кадр XChaCha20-Poly1305. HELLO версии 3 подписывается Ed25519. Отпечаток `nxx1…` считается из публичного X25519, не из фразы.
- Сейф: журнал `map.bin`. Файл режется на 16 КБ. Каждый чанк шифруется отдельно. Идентификатор — SHA-256 шифртекста. Чужой держатель получает шифртекст и не получает ключ файла.
- В сеть кладётся не больше трёх чужих копий и не две на один и тот же ключ. Своя нода в эту тройку не входит.
- Владелец время от времени спрашивает случайный чанк. Ответ — отпечаток шифртекста вместе с одноразовым вопросом. Неверный ответ снимает копию сразу.
- Молчание дольше льготы (по умолчанию 24 часа) тоже снимает копию. Уже лежащие чужие шифртексты из-за рейтинга не стираются. Новые чанки этому отпечатку не выдаются 30 суток. Рейтинг знает только тот владелец, который сам поймал отказ. Общего голосования сети нет.
- Вторая копия журнала лежит у контакта под меткой из ключа сейфа. Контакт отдаёт её только соединению с тем же отпечатком. Сети, которая искала бы метку сама, нет: без живого контакта одной фразы мало.
- Отзыв устройства подписывает ключ ноды. Журналы сливаются по подписям, более длинная копия без отзыва отзыв не стирает. Текущее устройство само себя отозвать не может. Если унесли сами двенадцать слов, отзыв не помогает: ими заводится новое устройство.
- Каталог `drive` — открытая папка рядом с шифртекстом. Файл, положенный туда, попадает в сейф. Это не зашифрованный диск.
- Профиль `lab` — прямой TCP. Луковый контакт он отвергает.
- Профиль `onion` слушает только `127.0.0.1`, звонит только на v3 `.onion` через SOCKS5 без пароля и не публикует прямой IP. Если адрес не задан, нода запускает бинарник `tor` и берёт имя из файла `hostname`. Нет бинарника — старт с ошибкой, фиктивный адрес не подставляется.
- Живой прогон с Tor 0.4.9.15 поднял два настоящих v3-адреса и провёл между ними одно сообщение. Узлы после проверки остановлены. В обычный `npm test` этот прогон не входит.
- Очередь: узел хранит шифртекст и отдаёт его только отпечатку, который очередь открыл. Чужой узел открытый текст из записи очереди не достаёт. Это не двоичный протокол simplexmq и с серверами SimpleX не стыкуется.
- Описание файла: подпись Ed25519 и список хешей чанков. Поля адреса и порта в описании нет. Получатель собирает байты и сверяет хеш. Это не провод XFTP SimpleX.
- `--miner` не кладёт свои файлы в бесплатные копии и подписывает объявление объёма. Чужие чанки принимает. Оплату не проверяет и эпоху не открывает.

## Чего в коде нет, хотя текст задания это обещает

- Формула бесплатного места `S / 3` не считается. Майнер просто не раздаёт свои файлы. Обычная нода раздаёт файл на живые контакты и без накопленной квоты.
- Порог «не принимать чужое, если свободно меньше 16 ГиБ» не проверяется. В лабораторном профиле чужих блобов не больше 64 МиБ — это единственный потолок.
- Плата в TON, USDC, ETH и BTC не отправляется и не проверяется. Внутренней биржи NXX нет.
- Магазин карт сборки, FUSE, WinFsp и поставщик файлов Android не сделаны.
- Windows и macOS отдельными сборками не выпущены. Тот же `node` на них может запуститься, установщика под них нет.
- iOS не начат. По заданию там и не должно быть ноды-хранилища.
- Рейтинг не общий для сети. Две ноды не знают чужих штрафов.
- Разнос копий по странам не проверяется.
- Один ключ на нескольких машинах не собирается в одну полосу места. Каждая установка — свой `deviceId` и свой журнал, пока журналы явно не слиты.
- Веб-страницы биржи, подписки и «глобального облака» рисуют цифры в браузере. За ними нет ноды.

В `linux-node/SPEC.md` абзац про транспорт раньше писал, что очередь и кадр ещё не сделаны, хотя версия 0.10.0 их уже содержала. Эта фраза исправлена: свой формат есть, совместимости с simplexmq нет.

## Android 0.1.2

Телефон умеет то, что Linux умел в паре «чат и файл», и не умеет ничего из сейфа 0.2–0.10.

Сделано:

- те же 12 слов и тот же отпечаток, сверка с векторами Linux;
- HELLO v3, прямой TCP, порт по умолчанию 4377;
- чат и файл кусками по 16 КБ по уже открытому каналу;
- локальное хранение принятого файла в каталоге приложения, куски закрыты ключом сейфа;
- строка контакта `nexxus:1:…`, копирование, выбор файла, уведомление о канале.

Не сделано:

- журнал `map.bin`, слепые копии, проверка чанка, льгота, штраф;
- каталог `drive` как открытое зеркало сейфа;
- отзыв устройства;
- профиль `onion`, Orbot, встроенный Tor;
- очередь и описание файла без адреса;
- режим майнера и любая оплата;
- фоновая работа, которая переживает засыпание телефона. Служба есть, но это не нода на зарядке.

Подпись release-сборки сейчас отладочная. Для чужих телефонов так выпускать нельзя.

## Веб

Браузерная консоль нужна была, чтобы показать слова, контакты и идею облака. Она не заменяет `nexxus start`. Называть её сетью нельзя.

## Риски, если пользоваться уже сейчас

- `drive/` — открытые файлы. Каталог ноды нельзя отдавать другим пользователям машины и нельзя считать сейфом.
- Лабораторный профиль публикует IP. Для чужой сети это не анонимный режим.
- Луковый режим честен только вместе с настоящим Tor. Общий SOCKS или чужой `tor`-бинарник не проверяются этой сборкой.
- Три копии есть только пока живы три разных контакта. Две ноды — это одна чужая копия, не «несгораемый» архив.
- Штраф местный. Нода, которую оштрафовал один владелец, для остальных остаётся чистой.
- Майнер без оплаты выглядит как участник с диском, но договора и возврата денег нет.
- Android и Linux после 0.1.2 разошлись. Телефон не прочитает `map.bin` и не примет луковый контакт.

## Что можно проверить руками

1. Два Linux в одной сети: `lab`, обмен строкой контакта, чат, файл, появление копий, папка `drive`.
2. Тот же сценарий с `NEXXUS_TOR_BIN` и `node test-tor-live.mjs`, если есть выход в сеть Tor.
3. Android 0.1.2 только с другой стороной, которая говорит HELLO v3 по TCP. Сейф 0.10.0 так не проверяется.

## Порядок работ после аудита

Не добавлять новые обещания в интерфейс. Сначала догнать Android до журнала Linux, затем квоту `S / 3` и порог 16 ГиБ, и только потом оплату. Оплата без проверки транзакции в код не ставится.
