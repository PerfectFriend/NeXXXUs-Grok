# Руководство пользователя NeXXXUs

Это руководство про то, что уже запускается. Оно не описывает биржу, подписку и магазин: их ещё нет.

Сейчас есть два разных приложения.

- **Linux-нода 0.10.0** — сейф, копии, папка `drive`, по желанию Tor и режим майнера.
- **Android 0.1.2** — чат и передача файла по обычному адресу в сети. Сейфа сети на телефоне нет.

Веб-страница в браузере — памятка. Она не соединяет компьютеры.

## Перед первым запуском

Запишите двенадцать слов на бумаге и уберите её. Экран их показывает один раз. Кто знает слова, может открыть сейф и завести новое устройство. Отзыв старого устройства от этого не спасает.

Не кладите в ноду то, что нельзя потерять, пока у вас нет трёх разных живых контактов. Две машины хранят одну чужую копию, не три.

Папка `drive` внутри каталога ноды — обычные файлы. Её видно тому, у кого есть доступ к диску. Шифртекст лежит отдельно, в `blobs/`.

## Linux: два компьютера в одной сети

Нужен Node.js 22 или новее.

```bash
git clone https://github.com/PerfectFriend/NeXXXUs-Grok.git
cd NeXXXUs-Grok/linux-node
chmod +x install/install.sh
./install/install.sh
export PATH="$HOME/.local/bin:$PATH"
nexxus start
```

Панель открывается на этой же машине: [http://127.0.0.1:4378/](http://127.0.0.1:4378/). Сеть слушает порт 4377.

На второй машине то же самое. Если порт занят:

```bash
nexxus start --data ~/.nexxus-b --port 4477 --http 4478
```

Дальше:

1. На каждой панели скопируйте строку контакта. Она начинается с `nexxus:1:`.
2. Вставьте чужую строку в поле связи и добавьте контакт.
3. Адрес в строке должен быть достижим со второй машины. В одной домашней сети это обычно адрес Wi-Fi, не `127.0.0.1`.
4. Когда контакт «в сети», можно писать и класть файлы.

Файл можно положить в папку `drive` каталога ноды. Нода сама разрежет его и, если есть живые чужие ноды, разложит копии. Удаление файла из этой папки удаляет его из сейфа.

Свои двенадцать слов больше не печатаются. Чтобы поднять ту же ноду заново, их передают при старте:

```bash
nexxus start --mnemonic "двенадцать слов сюда"
```

Чужие слова в команду попадают в историю оболочки. Для постоянной ноды лучше один раз создать её в нужном каталоге и дальше запускать без фразы.

## Linux: луковый режим

Этот режим не придумывает адрес и не включает «анонимность» галочкой. Нужен настоящий Tor.

Если пакет `tor` уже установлен и пишет имя в `hostname`:

```bash
nexxus start --profile onion --data ~/.nexxus
```

Нода слушает только localhost и публикует тот `.onion`, который записал Tor. Прямой IP в этом профиле не принимается. Лабораторный профиль, наоборот, не звонит на `.onion`. Смешивать их нельзя: оба конца должны быть в одном профиле.

Если Tor уже запущен отдельно и имя лука известно:

```bash
nexxus start --profile onion --tor-socks 127.0.0.1:9050 --advertise ВАШЕ_ИМЯ.onion
```

Проверка двух живых луков на машине разработчика:

```bash
NEXXUS_TOR_BIN=/путь/к/tor node test-tor-live.mjs
```

Обычная установка эту проверку сама не гоняет.

Пока лук поднят, контакт выглядит как обычная строка `nexxus:1:…@имя.onion:порт`. Её так же копируют второй стороне. Скорость не обещается. Если за минуту связи нет, сначала смотрят, что процесс `tor` дошёл до сети, и только потом ищут ошибку ноды.

## Что означают состояния

- **В сети** — канал с этим контактом сейчас открыт.
- **Копии** — сколько чужих нод держат файл по журналу, не больше трёх.
- **Без новых чанков** — этот владелец сам поймал отказ или молчание и временно не кладёт сюда новое. Чужие уже лежащие шифртексты из-за этого не удаляются.
- **Майнер** — узел обещал диск и не кладёт свои файлы в бесплатные копии.

Майнер пока не продаёт место. Платежа в TON, USDC, ETH и BTC нет. Флаг нужен, чтобы отличить узел, который только хранит чужое, от узла, который раскладывает своё.

## Отказ и возврат

Если нода погасла, владелец ждёт льготу, по умолчанию 24 часа, и не снимает копию сразу. После льготы копия в его журнале снимается, и новые чанки этому контакту не предлагаются 30 суток. Поднять ту же ноду с тем же каталогом можно в любой момент. Вернуть уже снятую копию можно только новой раскладкой, когда штраф кончится или появится другой контакт.

Отозвать можно другое своё устройство, не то, за которым сидите. Сейф из-за отзыва не пересоздаётся. В панели 0.10.0 это действие ещё не выведено кнопкой: оно есть в программе ноды и в тесте.

## Android 0.1.2

Телефон ставится отдельно от сейфа Linux. Он умеет говорить со старым каналом 0.1.2: чат и файл по IP.

1. Поставьте APK из релизов репозитория или соберите `android` сами (SDK 34, JDK 17).
2. Разрешите установку из неизвестного источника только на время установки.
3. Откройте приложение, запишите двенадцать слов, подтвердите, что записали.
4. Нажмите «Слушать сеть». В поле адреса должен быть IP телефона в Wi-Fi, не `127.0.0.1`, если второй участник — другой телефон или компьютер.
5. Обменяйтесь строками контакта и нажмите связь.
6. Чат и файл ходят, пока приложение не убито системой и оба адреса доступны.

Не ждите от этого APK копий в сети, лука и папки-сейфа. Телефон их ещё не умеет. Не оставляйте его «нодой на зарядке»: он не займёт диск под чужие чанки.

Сборка release сейчас подписана отладочным ключом. Для круга своих испытаний это терпимо. Для публикации людям нужен отдельный ключ подписи.

## Чего не делать

- Не считать веб-страницу биржи кошельком.
- Не отправлять никому оплату «за гигабайты NeXXXUs»: договор в протоколе не проверяется.
- Не публиковать каталог `drive` и файл `identity.bin`.
- Не открывать луковый профиль без своего Tor.
- Не ждать, что Android 0.1.2 прочитает сейф Linux 0.10.0.

## Если связь не поднимается

- В строке контакта должен быть адрес, который вторая сторона реально может открыть. `127.0.0.1` виден только этой машине.
- Оба конца в одном профиле: либо оба `lab`, либо оба `onion`.
- Порты 4377 и 4378 не заняты другим процессом. Панель всегда только на localhost.
- Для лука процесс Tor жив, а в контакте ровно 56 символов имени и суффикс `.onion`.
- Файл больше 64 МиБ нода не режет: это предел текущей версии, не предел диска.
